# 公开校准集 · 评审启动包（分发说明）

本包**可独立分发**：把整个目录交给一位评审员，他不需要任何其他材料就能完成 90 个单元的评审。

每个评审单元＝一段题干（场景与可接受边界）＋一段**候选输出**（已经写好的系统回答）。
评审员判的是候选输出落在边界的哪一侧，不是评价题干本身。

## 包里有什么

| 文件 | 用途 |
|---|---|
| `review_prompt.shared.v1.1.0.md` | 评审正文，两侧共用，只有身份行不同 |
| `output_format.md` | 输出字段与取值 |
| `scoring_anchors.json` | ②③ 类数值评分锚点（五档，每档一段行为描述） |
| `cases/public_calibration_cases.jsonl` | 90 个评审单元全量（题干＋候选输出） |
| `batches/batch_01.jsonl` … `batch_09.jsonl` | 分批清单，每批 10 个单元 |
| `hard_gates.json` | 硬门术语表 |
| `identity_lines.yaml` | 两侧身份行与各自的输出文件名 |
| `pack_manifest.yaml` | 文件清单与哈希 |

## 分发怎么做

1. 从 `identity_lines.yaml` 取对应一侧的身份行，填进 `review_prompt.shared.v1.1.0.md` 顶部的身份行位置。
2. 把 `pack_manifest.yaml` 里 `review_prompt.sha256` 的值告诉评审员，
   让他填进每条记录的 `review_prompt_hash`——**不要让评审员自己算或自己编**。
3. 按批交付，每批 10 个单元，回收该批 JSONL 后再发下一批。
4. 两侧的输出各自单独回收，**不要把一侧的结果给另一侧看**。

## 本包不含什么，以及为什么

本包**不含**：项目进度状态、内部编号与决定、Commit 哈希、既往审查结论、另一侧的评审结果，
以及**每个候选输出被构造时落在边界哪一侧的标签**。

最后一项要特别说明：这些候选输出是照着「落在界内」和「明确越界」两种意图分别写出来的，
写的人知道每一份是哪一种。那份对照表不进本包——它一旦随包发出去，
测出来的就是评审员抄标签的能力。

道理很直接：分歧率要测的是两位评审员各自的判断。
一旦评审员知道「上一轮别人怎么判的」或「项目现在卡在哪」，他就会往那个方向靠——
测出来的一致，是靠过去的，不是各自看出来的。
