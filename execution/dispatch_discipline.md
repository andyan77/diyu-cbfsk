# 派发纪律 · BR0-EP00 落盘

一页纸。写它的理由很直接：**同一 worktree 双窗口并发已经出过两次事**。成本一页纸，代价是一次返工。

本文件不是流程平台，也不是调度系统。它只规定三件事：worktree 归属、同一裁决不得同时下发两个执行窗口、提交前断言门命令链的使用时点。

---

## 一、worktree 归属

一个执行窗口 = 一个分支 + 一个 worktree + 一份明确的允许写入文件清单。

| 规则 | 内容 |
|---|---|
| 默认执行方式 | **串行**（`default_execution_mode: SERIAL`）。依赖上可并行 ≠ 同 worktree 可并发写。 |
| 同 worktree 并发写 | **禁止**。两个窗口写同一个工作树，第二个窗口看到的是第一个窗口写到一半的状态。 |
| 真并行的前置 | 独立分支 ＋ 独立 worktree ＋ 路径无重叠或重叠部分已显式冻结 ＋ 共享合同已冻结 ＋ 集成/迁移/lockfile 只有一个 owner ＋ 只有一个集成窗口 ＋ 合并后刷新基线 |
| 默认禁止并发编辑的文件 | 数据库 migrations、领域 contracts、公共 Schema、Task / Run 状态机、公共枚举、依赖 lockfile、全局配置、环境与部署入口 |

**不建设**：Worktree 调度平台、Agent 协作平台、分支编排服务、自动冲突仲裁系统、多代理工作流 DSL。冲突靠「不同时开」解决，不靠工具仲裁。

---

## 二、同一裁决不得同时下发两个执行窗口

一份 Founder 裁决（或一份执行 Prompt）在任一时刻只能有**一个**活跃执行窗口。

- 需要拆成两步时，前一步必须先出回执并被裁决为 `PASS` / `CONDITIONAL`，才能下发后一步。
- 「A 窗口做文档、B 窗口同时做代码」也算两个窗口——它们会同时改 CI、同时改 README、同时算基线哈希。
- 窗口异常中断（掉线、超时、被打断）后，**不得**直接开第二个窗口接着做。先用 `git status --porcelain` 确认工作树状态，再决定是继续原窗口还是回滚重开。

判断依据很简单：如果两个窗口的产物需要在同一个 Commit 里落盘，它们就是同一个窗口。

---

## 三、断言门命令链

提交必须写成一条命令，断言不过则 `add` / `commit` **物理上不执行**：

```bash
python3 <assert_script> && git add <files> && git commit -m "<message>"
```

**使用时点**：

| 时点 | 是否用断言门 |
|---|---|
| 本包交付物落盘的那次提交 | **必须** |
| 修复上一次断言拦下的问题后重提 | **必须**（断言必须重跑，不得沿用上一次结果） |
| 纯文档错别字修正（L1 任务） | 可省，但仍须 `git diff --check` |

**严禁**：
- 先 `git commit` 再跑验证（「先提交后补救」）
- 把断言与提交拆成两条命令分别执行
- 断言脚本读的是被它自己生成的结果（自审假绿）

断言脚本必须至少覆盖：本包声明的每一条阻断性验收、以及「不该出现的东西没有出现」这一侧。只有正向断言不算验证过。

---

## 四、这一页不管什么

不管排期、不管人力分配、不管谁先谁后的业务优先级。那些是 Founder 的裁决，不是纪律。
