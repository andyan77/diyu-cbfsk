## 一、双轨制总路线（修订版）

**轨道 A｜Kernel Engineering**：维护对象模型、事实优先级、品类合同、知识状态机、评分卡、硬门、DecisionTrace、确定性约束、人设与叙事边界。
**轨道 B｜Reality Evidence**：产生真实模型对比、真实专家修改、真实品牌任务、真实内容审核、真实付费意愿、真实运营反馈。

关键修订（针对单人团队的日历风险）：

1. **轨道 A 只响应轨道 B 提出的问题**。职责表述从「保留和继续维护」改为「按现实证据的问题清单形成候选改进」；无对应问题编号的内核扩建一律不开工。本仓的显性行为偏好是写合同（candidate/m2 七万九千行插入、零次模型调用，E1）——不给这个偏好留自主扩张的口子。
2. 并发执行包上限 2（FR-GRANULARITY-005）期间，**轨道 B 至少占 1**。
3. 循环固定为：现实证据提出问题 → Kernel 形成候选改进 → 评测验证 → 现实任务复测 → 再决定是否晋级。反向（Kernel 扩大→治理扩大→最后找场景）判定为路线违例。

## 二、产品定位与架构

### 2.1 对内工程定义

继续使用「笛语跨品牌跨品类服装搭配专家内核」。

### 2.2 对外产品定义

停用「数字化顶级服装搭配专家」作为已成立的产品主张（NG-03 精神的对外延伸）。对外定义：

> **服装品牌专业搭配决策与内容智能层**——现有工具负责执行，本产品负责决定什么值得执行、为什么执行，以及所有内容如何共享同一个专业判断真源。

明确不替代：ERP/PIM/POS、虚拟试穿、视频生成、CMS、发布平台、数据中台、交易基础设施。

### 2.3 架构：六层保留，Skill 是编译产物

六层架构（ADR-001）保留：L1 知识层 / L2 领域内核 / L3 人设平面 / L4 叙事平面 / L5 交付面 / L6 评测与治理。L1—L4 为 Domain Core，L5 为交付形态——内容与 API 只是 L5 的两种投影，不是两套系统。运行层与 API 层的建设时点维持 ADR-001 原判（M6 与商业形态裁决之后）。

**Skill 的准确身份：领域内核的低成本可执行投影（编译产物）。** 单一真源在合同层（EQ-1），Skill 可重编译、可多投影、可被下一代模型吸收而不伤及资产本体。编译两个：

- **`diyu-styling-core`**（L2 投影）：品牌与受众解析、商品语义、造型诊断、候选生成、排除理由、多目标取舍、副作用、失效条件、替代方案、DecisionTrace。
- **`diyu-persona-narrative-projector`**（L3＋L4 投影）：从专业判断发现叙事命题、读取人设档案、检查历史观点冲突与无新价值重复、生成平台内容、输出人设状态增量建议。

人设历史保存在 Skill 外（YAML 台账）；硬约束由确定性脚本执行（D-29 三条为验收标准）；品牌事实与货盘来自外部数据。人设冲突检测放确定性校验层（本质是台账比对），不放 Skill。

### 2.4 交付物：十一件套决策包

每个任务输出：① 多个合法搭配候选；② 推荐方案；③ 排除理由；④ 副作用与失效条件；⑤ 缺货/预算变化替代；⑥ 搭配核心命题；⑦ 叙事骨架；⑧ 指定账号与平台内容；⑨ **成图（外采视觉装配线组装）**；⑩ DecisionTrace；⑪ 审核与反馈入口（含 AIGC 合规检查单）。

其中十件对应 PRD 6.2 既有输出对象（E1），新增的只有成图与反馈入口。**⑨ 不是可选项**：服装内容没有图不进客户「可发布」分母，Gate 2 当场坍塌；视觉自研是战略自杀，不接视觉是产品自杀，外采组装（按调用计费的成熟 API）是唯一活路。

## 六、Reality Gates 与三结果（修订版）

以下为建议值，由 Founder 在 EP05 预注册时冻结。

### Gate 1｜相对强模型的专业增量
D vs A 盲评偏好显著（n≥85，α=0.05）；严重专业错误率 ≤2%（分母预定义）；品牌/库存/安全硬门断言 N≥600 零检出；被排除合法候选可追溯。

### Gate 2｜相对人工流程的效率增量
D vs H：直接发布或轻改比例 ≥75%；单包中位修改时间较 H 显著下降（经工作台测量，不许把「人工在背后大量修复」算进模型能力——干预严重度分布必报）。

### Gate 3｜叙事与人设增量
叙事结论对专业决策可追溯率 100%；人设硬冲突断言零检出（率上界表述）；事实被人设覆盖零检出；相对去掉人设叙事层的版本，可发布率或修改量显著改善。**不达标→人设连续性降级为可选模块，不再作为一级能力投入。**

### Gate 4｜跨品牌迁移（防游戏版）
同一 Skill 版本零 diff 通过第 N+1 品牌持出评测；**含品牌真源包编写在内的单品牌接入总工时 ≤1 人日**（接入成本不许从 Prompt 工程改名为知识工程后宣称达标）；未见品牌错误主要归因于品牌事实不足而非通用机制失效。

### Gate 5｜商业意愿（硬版）
3 个真实设计伙伴；2 个持续提供商品/任务/修改反馈；**≥2 家非关联客户实际付费且愿意付第二次**（付费触发条件、LOI、「客户很感兴趣」一律不计）；客户指派品牌侧审核人并同意回传修改与发布状态。

### 三结果决策树

| 结果 | 条件 | 动作 |
|---|---|---|
| **A｜完整内核成立** | 五门全过，且消融显示 D 对 B/C 有显著增量 | 恢复 M3/M4（有边界蒸馏，源头改为运营蒸馏）；此时才生成隐藏集（COND-011 关闭）；逐步实现 M6 编译器；商业维持内容先行、API 第二步 |
| **B｜Skill＋约束已足够** | C 达到 D 的 90—95%，D 成本复杂度显著更高 | 停建完整运行内核；仓库保留为知识/评测/治理源；产品化 Skill＋校验器＋轻量状态。**这不是失败，是避免把同样能力重新实现十遍** |
| **C｜不能击败强模型** | D 对 A/H 无显著增量，或专家分歧大、客户不付费 | 停止以「专家内核」继续投资；转向定制内容服务或行业咨询；不建 4,000—6,500 知识单元、不建隐藏品牌、不建企业平台 |

任一现实证据不成立，都不得解锁大规模蒸馏与系统平台化——**这句话写进裁决正文，不写进附录。**

## 七、反馈主干

### 7.1 早期对象（L6 正交，不动 M1 冻结）

`ExperimentOutcomeEnvelope`：run_id / arm_id / decision_id / tenant_scope / brand_id / 输入快照引用 / 输出引用 / expert_review（reviewer_id、accept|minor_edit|rework|reject、edited_fields、reason_codes、professional_error_class、legitimate_alternative、applicability_boundary、failure_condition）/ publication（published、channel、pre_publish_edit_severity）/ engagement 与 commerce 子块（**可选字段，L1/L2 模式有生产者后启用**，早期允许为空——不给不存在的数据流建必填模型）。

**捕获率按事件类型分别设阈**（分母＝经工作台流转的任务数）：专家审核 ≥90%（前提：编辑发生在工作台内）；发布确认 70—80%（一键回填）；曝光 40—60%（周期性平台导出，best-effort）；交易 <20%（best-effort，明确标注，不入护城河记账）。

商业成立后（结果 A/B 确认），再在下一版 PRD 正式加入 `OperationalFeedbackBundle`。

### 7.2 四层学习栈（修改数据的消化机制——没有它，账本只是仓库）

- **T1** 重复修改模式 → 确定性规则挖掘（进现有 checker 体系）；
- **T2** 每租户 before/after 修改对检索记忆，推理时注入；
- **T3** 修改 → 评测集扩充（每类严重错误自动生成 negative fixture，与 EQ-3 同构）；
- **T4** 数据量与权属允许后的偏好微调（远期，默认不承诺）。

必测两个指标：**修改→已部署改进的转化率**、**修改到上线周期**。每周复盘将每条修改归因到四通道之一或显式丢弃。产品越好修改越少的数据枯竭悖论，用定期插入校准任务（要求显式评分而非只在错时才改）对冲。

### 7.3 数据权属（第一份客户合同就写）

品牌层（私有、按租户隔离、客户可审计）与通用机制层（只允许从去标识聚合中提炼）分层；合同条款：允许衍生聚合学习、禁止品牌可识别内容出层；新增 Guardian 判据：**共享层不得出现任何租户特异 token**（配 negative fixture）。

## 八、外部专家机制（制度＋采购）

### 8.1 角色（进 role_operating_model，须裁决）

新增 `EXTERNAL_DOMAIN_EXPERT_REVIEWER` 与 `DOMAIN_EXPERT_ADJUDICATION_PANEL`。Founder 保留产品范围、商业取舍、风险接受与最终发布权，**不再默认充当服装专业真理唯一裁决者**。GPT/Claude 降为候选生成、反例、分歧暴露、批量检查与评审辅助，无最终专业裁决权。

### 8.2 组成与采购（两版方案都缺的部分，本版补齐）

三角色覆盖：资深搭配/陈列/造型专家、商品企划或买手、零售内容或门店运营。采购口径（E3，①阶段校准）：时薪 200—500 元，双盲×100+ 任务，预算封顶 5 万元；利益独立性写成可查验合同条款（与 Founder 及设计伙伴无雇佣/亲属关系），**模型评审一律不得计入专家盲评**；每人单日评审上限（防评审疲劳）；评审员先用 90 例校准集标定，分歧率超阈重新校准。

### 8.3 分歧处理

硬约束分歧→必须裁决；机制分歧→判断是否一方机制错误；开放决策分歧→判断是否均在可接受决策边界内（D-28 三分类照用）；重大分歧→第三名专家复核。**不强行把专家意见压成唯一答案；最有价值的产出不是分数，是修改轨迹**（8.1 的 YAML 字段即为此设计）。

## 九、知识工程新规则

1. **取消数量崇拜**：4,000—6,500 知识单元、25,000—50,000 回答、8,000—15,000 评测用例不再是成功指标，只是成本上限。
2. **方法升级**：「模型生成—模型攻击—Founder 接受」不再是主要知识来源；改为**模型辅助的专家知识工程**——模型出候选/反例/分歧/一致性检查，真实专家修改/纠错/补失效条件/判定合理多解/裁定迁移价值。运营蒸馏（真实任务出题）取代模型自蒸馏（模型互相出题）。
3. **知识三层**：通用机制层（跨品牌）/ 品牌私有层 / 租户反馈层（默认不跨租户）。
4. **通用知识晋级条件**：至少两个独立真实案例＋两个品牌＋一条负案例＋一次跨品牌 Holdout＋无未解决专家分歧＋明确适用与失效边界。纯模型生成永远停在候选态（P-06 不变式保留）。
5. **每个正式知识单元必有证据**：权威来源 / 外部专家修改 / 多真实案例 / 多品牌复现 / 明确反例，至少其一。

## 十、商业切入与财务假设

- **首发产品**：从商品货盘到专业内容资产的决策包（2.4 十一件套），按服务卖不按工具卖（中国市场工具付费锚点仅每月几十至几百元，服务锚点每月数千至数万元，E2 前版核验）。
- **定价假设**（E3，Wizard-of-Oz 实测校准）：品牌基础费 3,000—5,000 元/月起（锚定替代 0.5 个内容运营人头）＋内容包量费＋品牌真源包编写 onboarding 单独计费＋外部专家审核增值项。
- **单包成本目标**（E3）：模型＋视觉 API <50 元/包，专家审核抽检摊销另计——①阶段实测，若成本结构撑不住毛利，定价或形态在 Gate 5 前调整。
- **首发客户**：中型品牌（优先自有抖音/小红书店播闭环者）、多品牌代运营（作为渠道与设计伙伴，警惕蒸馏风险，合同防护）、电商内容团队。暂不做：成熟 AI 栈大集团、消费者 B2C、要求 GMV 分成者、不愿回传反馈者（不作为数据飞轮客户，只按工具/服务收费）。
- **纪律**：无可靠归因前不做 GMV 分成、不承诺提升销售、不按生成量计价；对外宣称维持三层分离（仿真证据/内部评审/真实市场证据），不得混用。
