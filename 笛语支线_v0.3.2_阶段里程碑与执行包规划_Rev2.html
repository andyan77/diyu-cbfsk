01 · Executive verdict

总裁决：先做垂直价值，后做横向完整

最高风险不是数据库或页面能否写出来，而是最终交付包能否在公平条件下明显胜过客户自己使用普通 LLM。真实样品先行，公平对照随后，工程复杂度必须为差距服务。

推荐执行形态：一条内容主线 + 一道独立安全门 + 一套极薄公平对照

主路径：BR0 → BR1-EP00（1 例 B1 公平对照）→ BR1-EP01…04 → BR2 → BR3 → BR4（10 例优越性对比）→ BR6 → BR7（品牌方盲化选择）→ BR8。条件支路：BR5 在 BR4 后与 BR6 逻辑并行。

先见成品EP00 不写代码、不定完整 Schema；同题同事实与 B1 Fact-fed One-shot 比较，Founder 只给 YES / CONDITIONAL / NO。
功能价值BR4 用 10 个预先固定案例判断内容制作交付包是否达到 CLEARLY_SUPERIOR，而不是看字段、页数和 Trace 长度。
真实对手主基线是事实已喂齐的同等级普通 LLM；B0 裸问不得作为成功证据，B3 只诊断 Runtime 是否超越 Prompt 编译。
安全独立Delivery Safety Gate 仍为独立硬门。好内容不能豁免错误 SKU、库存、事实、权限或安全违规。
工程边界不建评分卡、对比 Runner、评测控制台或回归基线库；模块化单体、单 PostgreSQL、单 Worker、OSS、ECS、无 Billing。
02 · Functional value standard

功能价值唯一标准：公平条件下，内容制作交付包必须显著优于普通 LLM

这项比较只测最终产出物，不测项目自证。它不替代安全门，也不等同于客户付费结果。

SUCCESS-FV-01｜同题、同事实、同等级模型、同输出合同

笛语支线的功能价值只有在中性呈现、随机顺序、输入等价的条件下成立。系统不能靠对手缺数据、输出更长、排版更漂亮或暴露更多内部结构取得假胜利。

同题场景、受众、商业目标、目标平台和任务要求完全一致。
同事实商品事实、品牌规则、库存、图片、禁用项和不确定性完整等价。
同模型尽量使用同一 provider / model / version；差异必须如实披露。
同输出合同两边都交 3 候选、推荐取舍、3 Hook、正文/口播、脚本、镜头和商品引用。
同中性模板去标识、统一格式、随机 A/B；不以 Logo、文件数量、Trace 长短暴露组别。
对照普通 LLM 获得什么回答的问题地位
B0 裸问只有任务描述，没有完整商品事实有数据的一方能否打败没数据的一方禁止作为成功证据
B1 Fact-fed One-shot全部事实、规则、库存、平台与同一输出合同；一次生成客户把资料直接贴给同等级模型能做到什么程度主对照，BR1/BR4 必做
B2 Serious User与 B1 相同，允许 2–3 轮追问与修正认真使用普通模型的客户能否追平BR4 从 10 例中预选 3 例抽样
B3 Compiled-prompt系统编译后的完整 Prompt 原样交给同一模型单轮生成完整 Runtime 是否超越“事实库 + Prompt 编译器”BR4 从 10 例中预选 3 例诊断

独立必要条件

Delivery Safety Gate

内容再吸引人，也不能豁免事实、SKU、库存、租户、品牌、品类与人工发布边界。

  • 安全失败即 BLOCK
  • 不与内容偏好相互抵消
  • 无综合总分
商业验证

客户采用与付费另行证明

公平对比证明功能价值；Pilot 中的接受、发布、编辑负担、复购与付费证据证明商业价值。

  • 商业结果只读
  • 不自动回流生产
  • 不替代功能价值门
定位层只回答什么判断方式禁止误读
L1 搭配决策是否专业、有洞察、有取舍，不是普通常识A / B / 持平 / 都不成立不能被 L2/L5 的结构优势掩盖
L2 事实正确SKU、库存、材质、价格与品牌事实是否真实PASS / BLOCK对照组同样必须获得完整事实
L3 平台原生是否真正适配平台，而非同稿换词A / B / 持平 / 都不成立不能只看标题和 Emoji
L4 可制作性脚本—镜头—SKU 是否对得上，能否直接执行A / B / 持平 / 都不可用整包更长不等于更可制作
L5 可复现追溯来源、版本、取舍与替换影响是否可解释PASS / FAIL结构优势不能单独证明内容代差
BR1-EP00

1 例早期穿刺

对 B1 做零代码 A/B。YES：笛语包明显更愿意拿去制作；CONDITIONAL：有方向但需改 Prompt/最小合同；NO：B1 更好或两份都不可。

BR4

10 例内容 MVP 定型门

B1 全 10 例；B2 与 B3 各预选 3 例。9–10 例明确偏好笛语且至少 2/3 个预先指定难例胜出，方可记为 CLEARLY_SUPERIOR。

BR7

品牌方盲化选择

用真实 Pilot 任务按同一中性方法比较，由实际使用者判断优先采用哪份；结果进入商业证据，不建设新界面或统计平台。

BR4 结果解释后续动作
CLEARLY_SUPERIOR笛语明确胜出 9–10 例，至少 2/3 难例胜出，Safety Gate 全通过；优势不能只来自 L2/L5允许宣称内容主产品功能价值定型，进入 Pilot
ADVANTAGE_BUT_NOT_DECISIVE笛语胜出 7–8 例承认有优势但无代差；先修内容合同/Prompt，不扩大 Runtime
NO_MATERIAL_ADVANTAGE笛语胜出不超过 6 例，或大量“两份都不可”不得宣称功能成功；暂停扩建，回到产品/Prompt 发现
PROMPT_COMPILER_DOMINANTB1 被明显击败，但 B3 与笛语基本持平内容产品可能成立，但完整 Runtime 增量未证明；优先收敛为更轻架构

04 · Phase model

五个阶段分别证明什么

每个阶段只回答一个商业或工程问题。不能用后续平台能力反向扩大早期施工范围。

1
BR0–BR1

模型能否先长出一份明显胜过 B1 的可卖样品？

先在聊天窗口用同题、同事实、同等级模型和同输出合同完成零代码 A/B；通过后，Founder 再让代码复现这条优势。

  • 1–2 天 EP00；最多 2 次人工迭代
  • 笛语样品 vs B1 Fact-fed One-shot
  • 中性格式、随机 A/B、Founder 判断
  • 通过后才冻结最小字段并进入代码闭环
2
BR2–BR3

能不能安全复制？

同一系统能否服务多个 Tenant、多个 Brand，并保持规则、商品、库存和内容引用不串用。

  • Tenant 安全根
  • 同租户跨品牌
  • 共享确定性规则引擎
  • 定向返工与血缘
3
BR4

内容是否形成可重复的功能代差？

同一专业决策不仅要编译成平台原生、可拍摄内容，还要在 10 个预先固定案例中明显胜过 B1。

  • B1 全 10 例
  • B2/B3 各抽样 3 例
  • 9–10 例明确胜出
  • Safety Gate 独立通过
4
BR5–BR6

增强能力是否克制？

视觉是可选渲染；商业结果只读；Evidence 可以积累，但不能自动改写生产真源。

  • CONCEPT_ONLY
  • Publication Metric 导入
  • Knowledge Candidate
  • RegressionCase
5
BR7–BR8

真实品牌方是否也优先采用笛语包？

在真实 Pilot 任务中继续用中性 A/B，让实际使用者选择愿意拿去制作的交付包，并与付费、发布、复购证据一起裁决。

  • 2 Tenant / 3 Brand
  • ≥30 真实任务建议值
  • 恢复与安全演练
  • Founder Go/No-Go

11 · Execution cadence

执行组织与包级节奏

每个执行包都要小到能独立提交、大到能产生可验证运行增量。当前单人 + AI 模式优先稳定串行，不用“逻辑并行”伪装实际产能。

容量估算与当前实际执行模式

  • 20–24 周场景：仅在 2 后端/AI + 1 前端 + 1 产品/设计/QA 基本同时投入时成立，且不构成交付承诺。
  • 当前模式：Founder + AI 窗口；依赖图有效，日历需要按实际吞吐重新估算。
  • 单 worktree：一个时间只允许一个写入流；其他窗口只读分析或等待。
  • 真并行：每个 EP 独占 branch/worktree，文件边界互斥，migration/contract/lockfile 有单一 Owner。
  • 汇合：由一个集成者按依赖顺序合并；禁止两个窗口交错写同一候选分支。

每个里程碑固定节奏

1. Plan一页以内；锁目标、包、依赖、退出门。
2. EP1先做最小可运行核心，不提前横向铺开。
3. EP2–4按真实 Commit 即时编译下一包 Prompt。
4. Demo用户旅程、失败路径、可下载结果与成本。
5. Closeout统一审查与 Founder 裁决；不每包重复大审。

Founder 一页结论

v0.3.2 的合理粒度仍是 5 个阶段、9 个里程碑、25 个通用执行包 + 2 个视觉条件执行包。变化不是增加新执行包，而是把功能价值门嵌入现有 BR1-EP00、BR4 和 BR7：先用 1 例 B1 避免围绕错误样品写代码；BR4 用 10 例判断是否真的形成内容代差；BR7 再由实际品牌使用者判断是否优先采用。

建议开工口令：先锁 BR0 两包；随后只执行 BR1-EP00，并同步生成笛语样品与 B1 Fact-fed One-shot。Founder 在中性 A/B 下给出 YES/CONDITIONAL 后，再即时编译 BR1-EP01；不要提前生成剩余施工 Prompt。
规划依据：v0.3.2 最新裁决、历史 v0.3 Draft 的可操作用户闭环与模型 usage-cost 记录、Canonical Runtime Architecture v0.2 对基础模型能力必须由评测证明的边界，以及本轮新增 Founder 裁决：内容制作交付包在公平条件下显著优于事实喂齐的同等级普通 LLM，是支线功能价值成功的唯一标准。
